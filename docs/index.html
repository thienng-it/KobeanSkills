1. Zero-Clone Quick Start Install & Wiring

Initialize KobeanSkills inside any existing repository or empty directory in seconds. Zero global npm dependencies are required at runtime—the CLI uses pure Node.js standard library modules.

Fastest option for developers running Bun:

terminal — bunx
# Initialize directly from GitHub into the current repo:
bunx github:thienng-it/KobeanSkills init

# Verify installed companion tools (bd, betterleaks, graphify, d2, mmdc):
bunx github:thienng-it/KobeanSkills doctor

Works out-of-the-box anywhere Node.js ≥ 18 is installed:

terminal — npx
npx github:thienng-it/KobeanSkills init
npx github:thienng-it/KobeanSkills doctor

Zero Node/Bun required—ideal for Go, Rust, Python, or minimal Linux/macOS environments:

terminal — bash
curl -fsSL https://raw.githubusercontent.com/thienng-it/KobeanSkills/main/setup.sh | bash

Install once globally so every repository on your machine inherits KobeanSkills automatically via symlinks into ~/.gemini/, ~/.claude/, and ~/.codex/:

terminal — global install
# Install globally across Antigravity, Gemini CLI, Claude Code & Codex CLI:
bunx github:thienng-it/KobeanSkills install

# Cleanly remove all global symlinks anytime:
bunx github:thienng-it/KobeanSkills install --uninstall

Containerized sandbox with companion binaries (bd, betterleaks, osv-scanner) pre-installed:

terminal — docker
docker run --rm -v "$(pwd):/workspace" ghcr.io/thienng-it/kobean-skills:latest kobean init
No Black Box — What kobean init Actually Writes to Your Repo
  • Unpacks .kobean/: Copies pure declarative doctrine.md, skills/kb-*, roles/*.yaml, references/**, templates/**, and scaffolds .kobean/constitution.md + .kobean/mcp.json.
  • Wires All 4 Agent Runtimes: Creates symlinks (with Windows junction/copy fallback) in .agents/ (Antigravity), .claude/ + CLAUDE.md (Claude Code), .codex/ + AGENTS.md (Codex CLI), and .gemini/ (Gemini CLI).
  • Bootstraps PR Hygiene: Writes a clean .github/pull_request_template.md with Conventional Commit summary, Beads task IDs, and security/test checklists.
  • Never Leaks Secrets: Stores ${ENV_VAR} placeholders in .kobean/mcp.json and propagates placeholders—never plaintext credentials—into synced runtime files.

2. Mental Model: Why KobeanSkills Exists Architecture Principles

Raw AI coding agents fail in predictable, structural ways once a repository grows past a toy demo. Every directory and invariant inside KobeanSkills exists to permanently eliminate one of these five root failure modes:

Failure Mode in Raw Agents KobeanSkills Architectural Fix Deterministic Enforcer
1. Context Window Bloat
Loading 40 verbose prompts upfront wastes 30k+ tokens and causes instruction forgetting.		 Progressive Disclosure: Only 10 tiny SKILL.md frontmatter summaries (≤350 chars each) load at session start. Full runbooks, role contracts, and stack references load strictly when routed. scripts/lint.sh enforces exact skill count (10) & ≤350-char frontmatter descriptions.
2. Supply-Chain Script Risk
Copying random third-party skill repos pulls untrusted .sh/.py/.js hooks into your machine.		 Air-Gapped Distillation: Patterns from 25 pinned upstream repos (SOURCES.md) are distilled into pure Markdown, YAML, and offline HTML templates. Zero executable scripts inside content folders. scripts/lint.sh hard-fails if any .sh, .py, .js, .mjs, or .ts file appears in skills/, roles/, references/, or templates/.
3. Parallel Agent Collisions
Two concurrent subagents edit the same file and clobber each other's work.		 Disjoint Write-Glob Contracts: All 24 roles declare explicit writes and forbidden path globs in roles/*.yaml (e.g., frontend owns UI, content-architect owns src/data/**). scripts/lint.sh performs pairwise glob collision verification across build roles.
4. Markdown Task Drift
Agents invent competing TODO.md, tasks.md, and progress.md files that go stale immediately.		 Single Source of Task State: Beads (.beads/ managed by bd) is the exclusive dependency graph with atomic claiming (bd update --claim) and blocker tracking (bd dep add). doctrine.md Section 2 bans competing markdown checklists across every skill.
5. Hallucinated Diagrams & Docs
LLMs draw 30-node Mermaid hairballs pointing at renamed files and nonexistent functions.		 Commit-Pinned Atlas (kb-atlas): Grounds every claim in graphify AST graphs + exact file:start-end line citations pinned to HEAD SHA, capped at ≤15 nodes per diagram. kobean atlas check --strict verifies every line range exists on disk and detects git drift.

4. End-to-End Engineering Lifecycle Fast-Path vs. Full Spec Pipeline

KobeanSkills never forces heavy ceremony on trivial edits. kb-router evaluates scope first and picks the smallest pipeline that guarantees safety:

Ponytail Fast-Path 1 File · <20 Lines
Triggered when scope is crystal clear (e.g., typo, small config fix, isolated 1-function bug). Skips kb-spec and kb-plan entirely, executes inline at Level 1 with a unit/regression check, runs Ponytail minimalism, and verifies cleanly.
Flow: kb-router → Inline Role → Test/Lint → Done
Full Contract-First Pipeline Multi-File · Auth · DB · UI
Triggered for any new feature, schema change, ambiguous request, or security-sensitive work. Locks requirements, threat model, API contracts, and .beads/ dependency edges before writing a single line of implementation code.
Flow: kb-spec → kb-plan → .beads/ → kb-build → kb-review → kb-git/kb-ship
0
Deterministic AST Orientation explorer · graphify
Instead of burning 30 blind grep turns, explorer (read-only, Tier 2 flash) queries graphify-out/graph.json and produces CONTEXT.md mapping entry points, shared helpers to reuse, and exact test commands.
Outputs: CONTEXT.md, graphify-out/GRAPH_REPORT.md Gate: Shared utilities identified before designing anything new

Requirements, Existence Check & Threat Modeling kb-spec · po · threat-modeler
po runs a single Ponytail Ultra gate ("Does this feature need to exist, or does an existing mechanism already solve it?"), asks 1–4 Socratic clarifying questions via ask_question, and writes testable Given/When/Then acceptance criteria. Whenever auth, payments, PII, secrets, or untrusted input are touched, threat-modeler writes a STRIDE/DREAD threat matrix.
Outputs: specs/NNN-<slug>/spec.md, threats.md Gate: Zero ambiguous requirements or unmitigated auth threats

Outputs: plan.md, data-model.md, contracts/, .beads/ Gate: Zero overlapping file ownership across parallel tasks

Workers claim unblocked tasks (bd ready → bd update <id> --claim), follow strict Red-Green-Refactor TDD (failing test first), and apply Ponytail Full Mode (reuse project helpers → stdlib → installed packages; zero speculative wrappers). UI work runs through kb-ui (Impeccable craft or bold Taste-Skill + Chrome DevTools verification); architecture docs run through kb-atlas.
Outputs: Minimal tested diff, docs/atlas/**, closed .beads/ issues Gate: Red test observed failing, then green with full suite passing

Outputs: Rebased PR with template, ADRs, CHANGELOG.md, rollback plan Gate: Never force-push main; clean CI + verified release checklist

5. Smart Model Routing & Multi-Agent Escalation Doctrine Section 6

Spawning heavy reasoning swarms for a 5-line edit wastes minutes and quota; running a single lightweight turn across a 12-service refactor causes context collapse. KobeanSkills scales both agent topology and model tier systematically:

4-Level Orchestration Escalation Ladder

Level 1 · Inline Single-Agent0 Overhead
Default for <20 lines or single-role turns. Loads .kobean/roles/<role>.yaml directly into the active conversation with zero subagent spawn latency.
Best for: Quick fixes, single-file tweaks, focused Q&A
Level 2 · Targeted Subagents2–3 Roles
Uses invoke_subagent: spawns read-only research scouts to keep noisy exploration out of main context, or 2–3 non-overlapping self builders in parallel (e.g., frontend + content-architect).
Best for: Feature slices, isolated audits, UI + data builds
Level 3 · Programmatic DAGN ≥ 3 Fan-Out
Uses Python run_workflow (parallel, pipeline, agent) when fanning out over many independent modules (e.g., monorepo kb-atlas domain wikis or 5-role verification gates) and aggregating deterministically.
Best for: Large codebases, multi-domain wikis, bulk audits
Level 4 · Collaborative Swarmworkspace: share
Uses native /swarm with isolated repository working copies (workspace: "share") so write-heavy workers edit, compile, and run tests simultaneously with dedicated qa/reviewer verification before merge.
Best for: Multi-branch parallel feature engineering

3-Tier Smart Model Selection Matrix

Tier Antigravity Claude Code Codex CLI Assigned Specialist Roles & Workloads
Tier 1 · flash_lite flash_lite haiku codex-mini Trivial file/tag scans, schema & link checks, boilerplate formatting, high-volume JSON/grep filtering.
Tier 2 · flash flash sonnet gpt-5-codex 6 Roles: explorer (graphify), a11y-auditor, performance, supply-chain, tech-writer, release-manager.
Tier 3 · pro pro / inherit opus / sonnet-thinking o3 / gpt-5-high 18 Roles: po, threat-modeler, architect, api-designer, data-engineer, ui-ux-designer, atlas-architect, frontend, content-architect, backend, mobile, ml-engineer, devops, refactorer, debugger, reviewer, security, qa.
Stage 6.3 Pattern — Staged Handoff & Warm Subagent Reuse (send_message)

In compiled multi-target repositories (SwiftPM, Rust Cargo, Go workspaces, TypeScript monorepos) where UI depends on Core types: (1) backend builds and tests Core contracts first so public symbols compile cleanly → (2) frontend builds strictly inside UI write globs → (3) Read-only reviewer + qa fan out simultaneously → (4) When findings span Core and UI, the coordinator messages the existing warm subagents in parallel via send_message instead of cold-spawning fresh agents—preserving full context and cutting token/latency overhead.

Playbook 4

Systematic Root-Cause Debugging (Iron Law)

Enforces the Iron Law of Debugging: the agent is forbidden from guessing patches before reproducing the failure and proving the root cause with a failing regression test.

prompt — debug
Use kb-debug to investigate this error:
[Paste error log, stack trace, or failing test output]
1. Reproduce FirstExecutes the exact failing command or creates a minimal reproducer before reading/editing fixes.
2. Trace Blast RadiusUses graphify call graph to inspect every caller so fixes happen in shared root logic, not one symptom site.
3. Red Regression TestAdds an automated test that fails on the bug before modifying implementation code.
4. Minimal Green FixApplies the smallest root-cause patch and proves both the regression test and full suite pass.

8. Universal Cross-Agent MCP Manager Zero-Drift Sync Across 4 Runtimes

Every AI coding runtime expects Model Context Protocol (MCP) definitions in a different path and serialization format. KobeanSkills establishes .kobean/mcp.json as the single declarative source of truth and compiles it into all four runtimes automatically—preserving ${ENV_VAR} placeholders so secrets never touch version-controlled files.

Claude CodeJSON
Auto-synced to root .mcp.json with native mcpServers dictionary and env placeholders intact.
Antigravity IDEJSON
Auto-synced to .agents/mcp.json for instant workspace MCP server discovery.
Gemini CLIJSON
Auto-synced to .gemini/mcp_config.json (and ~/.gemini/config/mcp_config.json with --global).
OpenAI Codex CLITOML
Non-destructively serialized into [mcp_servers.*] blocks inside .codex/config.toml without touching other user settings.
bash — zero-drift MCP lifecycle
# 1. Audit configured connectors, cross-agent sync status, and missing .env keys:
bunx kobean-skills mcp

# 2. Install vetted presets (auto-wires Claude, Antigravity, Gemini & Codex instantly):
bunx kobean-skills mcp add postgres
bunx kobean-skills mcp add drawio
bunx kobean-skills mcp add github

# 3. Re-sync all 4 agent configs after manual edits to .kobean/mcp.json:
bunx kobean-skills mcp sync

Phase-Scoped Ponytail (YAGNI) Policy

OFF in kb-spec & kb-plan (Be Thorough)

Specs, threat models, and architectural plans must be exhaustive about edge cases and contracts. Only the po role runs one Ponytail Ultra gate at the start of kb-spec: "Does this feature need to exist at all?"

ON Full Mode in kb-build, kb-debug & kb-review

Reuse project helpers → stdlib → installed deps. Write the smallest complete diff. Tag shortcuts with // shortcut: <limit>, <when to upgrade>. Never cut: trust-boundary validation, data-loss error handling, security, accessibility, or explicit spec criteria.
